# ローカル日英翻訳アプリ 仕様案 v0.1

作成日: 2026-11-04（日本時間）  
状態: 初期の要件・設計案。2026-11-04に専用アプリの初版を実装した。現在の採用内容・検証範囲は [implementation.md](implementation.md) を参照。以下は実装済み機能の一覧ではない。

## 1. 目的と前提

他のアプリで読んでいる文章や、これから送る文章を、その場で日本語・英語に翻訳する個人用Macアプリを作る。Nani翻訳のような呼び出しやすさを参考にする。

### ユーザーが確認した要件

- 日本語 → 英語、英語 → 日本語の双方向に対応する。
- 翻訳処理をローカルで行い、初回セットアップ後はオフラインでも使える。
- サービス側の回数制限、月額契約、API従量課金を必要としない。
- 翻訳品質は「原文の意味を誤解なく伝えること」を優先する。
- スラングの網羅、細かな言い換え、ニュアンス解説は優先しない。
- 利用機はM4 Pro・メモリ48GB。

以下の画面構成、OS下限、保存設定、モデル候補、性能目標は、この要件を実装するための提案。Naniと同等の品質や、すべてのアプリからの取得を保証するものではない。

## 2. 初版の範囲

### 初版に含める

| ID | 機能 | 仕様 |
| --- | --- | --- |
| F01 | メニューバー常駐 | 翻訳パネル・履歴・設定・終了をメニューから開く。パネルを閉じても常駐を続ける |
| F02 | 選択テキスト翻訳 | 他アプリで文章を選び、ユーザーが設定したグローバルショートカットで翻訳する |
| F03 | クリップボード翻訳 | コピー済みの文章を、専用操作で取り込んで翻訳する |
| F04 | 手入力・貼り付け | パネルの原文欄を編集し、翻訳ボタンまたはCommand+Returnで実行する |
| F05 | 翻訳方向 | 自動・日本語→英語・英語→日本語。曖昧な入力では手動指定できる |
| F06 | 原文・訳文表示 | 原文と訳文を上下に表示。生成中・完了・中断・失敗を区別する |
| F07 | コピー | 完了した訳文をコピーする。コピー完了を短く表示する |
| F08 | 再翻訳・中断 | 同じ原文で再実行できる。生成を途中で止められる |
| F09 | ローカル履歴 | 保存を有効にした場合だけ記録。再表示・検索・個別削除・全削除に対応する |
| F10 | 設定・セットアップ | ショートカット、ローカルモデル、履歴保存、モデル保持、ログイン時起動、権限状態を設定・確認できる |

### 次段階に分ける

- 画面の範囲選択 → OCR（文字認識） → 翻訳。選択できない画像・スキャンPDFへの対応。
- 長文の分割翻訳と進捗表示。
- 翻訳しない前後の文章を、参考文脈として別欄から追加する機能。
- 用語集、訳文の書き出し、必要に応じた表現調整。

### 当面は対象にしない

- Webページ全体の置換翻訳、PDFファイル全体のレイアウト維持翻訳。
- 動画の連続字幕翻訳、音声翻訳、Windows・スマートフォン対応。
- クラウド翻訳への自動切り替え、アカウント、同期、課金機能。
- 原文アプリの文章を自動で置き換える機能。
- 翻訳モデルの自前学習、複数モデルによる毎回の相互校正。

## 3. 基本操作と画面

### 選択した文章を翻訳する

1. ブラウザ・PDFビューア・エディタなどで文章を選ぶ。
2. 登録したショートカットを押す。
3. アプリは、呼び出し元が前面にある間に選択テキストを取得する。
4. 小さな翻訳パネルを表示し、言語を判定して翻訳を開始する。
5. 原文の下に訳文を順次表示する。途中の文章には「翻訳中」と表示する。
6. 完了後に読む・コピーする。Escapeで閉じる。原文アプリの内容は編集しない。

文章を取得できなかった場合は空の原文欄と「文章をコピーして貼り付けてください」を表示する。無関係な古いクリップボード内容を、自動で代用しない。

### 翻訳パネル

- 上部: 翻訳方向の選択、状態表示。
- 中部: 編集可能な原文欄、読み取り専用の訳文欄。
- 下部: 翻訳／中断、コピー、再翻訳、履歴。
- 初期サイズ案: 幅560pt・高さ480pt。リサイズ可能にし、画面外にはみ出さない。
- 初回はポインター付近の画面内に表示し、以後はパネルの位置・サイズを保存する。
- まず訳文1つを表示する。解説・スラング分析・複数候補を通常画面に常設しない。
- 生成中の訳文を確定結果として扱わない。中断・出力上限到達時には未完了と表示する。
- VoiceOver、キーボード操作、ライト／ダーク表示に対応する。

### メニューバーメニュー

「翻訳を開く」「クリップボードを翻訳」「履歴」「設定」「終了」を置く。接続できない場合は、メニューまたはパネルに翻訳エンジンの状態を表示する。

### 履歴・設定

- 履歴: 日付、原文冒頭、翻訳方向を一覧表示。選択すると原文・訳文を再表示する。
- 履歴保存は初期状態でオフ。オンにした場合、初期保持件数は直近500件とする。
- 設定: ローカルモデル、言語の初期値、ショートカット、保存のオン／オフ、履歴削除、モデル保持時間、ログイン時起動。
- 初回設定: Ollama接続 → 導入済みモデル確認 → 必要ならモデル取得案内 → ショートカット設定 → 選択取得用の権限案内 → 試訳。
- モデルのダウンロードは操作前に容量とネット接続の必要性を表示する。初版では公式の導入手順に案内し、導入済みモデルを再確認する方式とする。

## 4. 翻訳の品質要件

優先順位は「意味の保持 → 訳抜け・追加の防止 → 自然で読みやすい文章」。自然さのために、原文の事実や断定の強さを変えない。

### 必ず評価する項目

- 否定、条件、例外、可能性、義務、依頼の強さを保つ。
- 数字、単位、日付、金額、固有名詞、URLを正しく扱う。
- 主語・目的語・時制・因果関係を、根拠なく補ったり変更したりしない。
- 段落・箇条書きを可能な範囲で保ち、文章の一部を要約して落とさない。
- 専門用語や一般的な慣用表現を、文脈に合った意味で訳す。
- 翻訳対象に書かれた指示に従って別の作業を始めず、文章として翻訳する。
- 省略や曖昧さがある場合、原文以上の具体性を勝手に足さない。

### 実装方針

- 最初は1回のモデル呼び出しで訳文を生成する。
- モデルごとの推奨入力形式を使う。TranslateGemmaには翻訳専用の形式を使い、解説用のJSON出力などを一律に強制しない。[S1]
- 出力の安定性を優先する生成設定から検証し、プロンプトと設定にバージョンを付ける。
- 過去の翻訳履歴を、次の翻訳の文脈に自動で混ぜない。
- 自己採点や逆翻訳だけで「正確」と判定しない。意味の確認は人による評価を含める。
- 目立つ数値・URLの欠落を検査する場合も、書式差との区別が必要。自動検査を品質保証として表示しない。

## 5. 技術スタック案

| 担当 | 採用案 | 理由 |
| --- | --- | --- |
| 対象OS | macOS 15以降・Apple Silicon | 個人用Macに対象を絞り、利用するAPIと検証範囲を揃える。実際のOSバージョンは実装前に確認する |
| 言語・開発 | Swift 6系、Xcode、Swift Package Manager | ネイティブUIとmacOS連携を同じコードベースで実装する |
| 通常画面 | SwiftUI | 翻訳欄、履歴、設定を構築する |
| 常駐・パネル | AppKitのNSStatusItem・NSPanel | メニューバー、画面位置、前面表示とフォーカスを制御する |
| 共通ショートカット | KeyboardShortcuts | 登録・変更用UIを利用する。依存バージョンは実装時に固定する [S2] |
| 選択テキスト | Accessibility API／AXUIElement | 呼び出し元の選択内容を取得する [S3] |
| コピー操作 | NSPasteboard、必要に応じてCGEvent | 明示的なクリップボード取り込みと、選択取得の補助に使う |
| 日英の判定 | NaturalLanguage／NLLanguageRecognizer | モデルを呼ぶ前にローカルで判定し、手動指定も提供する |
| 翻訳エンジン | Mac向けOllama | モデル管理とローカル推論をアプリ本体から分離する |
| エンジンとの通信 | URLSession、async/await、NDJSON | ローカルAPIのストリーミング表示とキャンセルを実装する [S4] |
| 履歴 | SwiftData（ローカルストアのみ） | 小規模な履歴の保存・検索に利用する。CloudKit同期は使わない [S5] |
| 設定 | UserDefaults | ショートカット以外の表示・保存設定などを記録する |
| ログイン時起動 | ServiceManagement／SMAppService | 設定でオンにした場合だけ登録する [S6] |
| ログ | OSLog | エラー種別や所要時間を記録する。原文・訳文は通常ログに出さない |
| 検証 | Swift Testing、必要箇所のみXCTest／XCUITest、手動の実機検証 | 翻訳処理と他アプリ連携を、それぞれ適切な層で確認する |
| 次段階の画面翻訳 | ScreenCaptureKit + Vision | 範囲画像を取得し、文字認識する [S7][S8] |

UIはMacネイティブを採用する。ブラウザだけでは他アプリの選択取得や常駐パネルを完結できないため、WebサーバーやWeb用フレームワークを追加しない。OllamaはDocker経由ではなくMac上で直接実行する。

初版はXcodeからビルドした.appを個人利用する想定。App Sandboxを有効にしない構成を出発点とし、Accessibility・コピー補助の実機動作を確認する。外部配布やApp Store対応を行う場合は、署名・公証・権限構成を別途設計する。

## 6. 翻訳モデルと実行設定

### 最初の比較候補

| 候補 | 役割 | 採否の判断 |
| --- | --- | --- |
| TranslateGemma 27B・Q4_K_M | 品質を優先する第一候補 | 意味の保持と速度を実測し、基準を満たせば標準にする。Ollama配布サイズは約17GB [S1] |
| TranslateGemma 12B | 速度・メモリとの比較候補 | 27Bに比べて品質を大きく損なわず、待ち時間を短くできるかを見る [S9] |
| Qwen3.6 27B | 翻訳専用モデルで課題が残る場合の追加候補 | 汎用モデルが優れていると決めつけず、同じ評価文章で比較する [S10] |

48GBは27B量子化モデルを比較するうえで現実的な容量と見込むが、ファイルサイズと実行時メモリは異なる。モデルは1つずつ動かし、実際のOS・他アプリ・入力長を含めて確認する。採用モデルと量子化形式は未確定。

### 初期設定案

- 接続先は `http://127.0.0.1:11434` に固定し、外部ホストへの変更を初版UIに置かない。
- `POST /api/chat`、`stream: true` で生成し、NDJSONを順に読む。[S4]
- モデルは導入済みのローカルモデルに限定し、クラウド実行へ切り替えない。
- 初期コンテキスト長は16,384トークンを比較の出発点にする。モデル情報と実測に合わせて調整する。
- 初版の入力上限案は2,000文字。サービスの利用制限ではなく、長文処理を追加するまでの処理範囲とする。
- 文字数だけでトークン数を断定しない。入力・プロンプト・出力の予算をモデルに合わせて検証し、超過時に原文を黙って切り詰めない。
- 出力上限の初期値は4,096トークン。上限到達は未完了として表示する。
- モデル保持時間は初期10分。設定で「都度解放」「10分」「常時保持」を選べるようにする。[S11]
- 起動時の自動プリロードは初期オフ。常時保持を選んだ場合も生成中以外に推論を繰り返さない。
- 同時実行は1件。新しい翻訳を始める場合、以前の結果が新しい画面を上書きしないようリクエストIDで制御する。
- まず120秒を全体タイムアウトの提案値とし、実測で調整する。接続失敗・モデルロード待ち・生成中を区別する。

## 7. 内部構成と処理の境界

```text
他アプリの選択 / コピー済み文章 / 手入力
                  ↓
      TextCaptureService・PermissionService
                  ↓
      TranslationCoordinator（入力・方向・実行状態）
                  ↓
      TranslationEngineプロトコル
                  ↓
      OllamaTranslationEngine → Mac上のOllama
                  ↓
      ストリーミング結果 → 翻訳パネル
                  ↓
      完了時のみHistoryRepositoryへ保存（有効時）
```

- UIはMainActorで更新し、テキスト取得・通信・保存の待ち時間で画面を止めない。
- エンジンのインターフェースを分け、将来MLXやllama.cppに替える場合も画面を作り直さずに済む構成にする。
- モデルごとの入力形式・生成設定はエンジン側のモデルアダプターにまとめる。
- 中断時は通信をキャンセルする。実際に推論資源が解放・停止されるかは、Ollamaの採用バージョンで確認する。
- 通信失敗時に勝手に再試行して二重生成しない。原文を残し、再試行操作を出す。

### 選択テキスト取得

1. 呼び出し元のアプリとフォーカス要素を記録する。
2. Accessibility APIから選択文字列を取得する。
3. 取得できなければ、設定で有効にしたコピー操作による補助を試す。
4. 補助も使えない場合は、コピー済み文章の取り込みまたは手動貼り付けに案内する。

コピー補助は初期オフとし、初期設定で説明して切り替えられるようにする。有効時は復元可能なクリップボードデータを退避し、コピーで新しく得られた内容だけを読む。別のアプリやユーザーがその後に更新した内容は、古い内容で上書きしない。復元できない形式がある場合は補助を実行せず、手動コピーに案内する。

パスワードなどの保護された入力を取得対象にしない。画面全体・文書全体・周辺の会話を暗黙に読み取らない。

## 8. 保存データとプライバシー

### 履歴レコード

`id`、`createdAt`、`sourceText`、`translatedText`、`sourceLanguage`、`targetLanguage`、`modelName`、`modelDigest`、`promptVersion`、`durationMs`を記録する。原文アプリの識別情報や画面画像は保存しない。

完了した結果のみ保存する。途中結果・失敗結果は通常履歴に混ぜない。保存オフでは、翻訳内容をアプリの永続ストアに書かない。

### 通信と権限

- 翻訳中はループバックへの通信のみを行う。原文・訳文を外部APIに送らない。
- Ollamaのクラウド機能を無効化したローカル運用をセットアップ手順に含める。設定変更時は既存の他の設定を保つ。[S11]
- インストール・モデル取得・依存パッケージ取得にはネット接続が必要。翻訳のオフライン動作とは分けて扱う。
- Ollama本体の更新確認・自動ダウンロードなどは別プロセスの挙動。翻訳アプリの外部通信ゼロと、PC全体の外部通信ゼロを混同しない。[S11]
- クリップボードを常時監視しない。ユーザーの呼び出し時だけ取得する。
- アクセシビリティ許可は選択取得機能で案内する。拒否されても手入力・貼り付けは使える。
- 画面収録許可はOCR導入時に初めて求める。
- 履歴は通常のローカル保存であり、アプリ独自の暗号化や完全消去を保証しない。個別削除・全削除は通常の履歴から参照できなくする機能として扱う。

## 9. 異常時の表示

| 状態 | 動作 |
| --- | --- |
| Ollama未導入・未起動 | 入力を保持し、導入・起動手順と「再確認」を表示する |
| モデル未導入 | 必要なモデルと容量の目安を表示し、取得手順に案内する |
| 権限なし | 対象の設定画面に案内する。手入力への導線を残す |
| 選択文字列なし | 入力欄を開く。古いコピー内容は勝手に翻訳しない |
| 言語判定が曖昧 | 翻訳方向の手動指定を求める。日本語を含むだけで機械的に決めない |
| 入力が長すぎる | 原文を保持し、初版の対応範囲と分割の必要性を表示する |
| 生成失敗・空の出力 | 失敗と表示し、再試行できる。完了履歴に保存しない |
| 途中中断・出力上限 | 訳文が途中であると明示する。完了扱いしない |
| メモリ不足 | 入力を保持し、他のモデル・設定で再試行できるようにする |
| スリープ・復帰後の接続失敗 | 接続状態を再確認し、必要なら再試行を表示する |

## 10. 品質・性能の受け入れ条件案

以下は今後確認する条件であり、達成済みの結果ではない。

### 翻訳品質

- 評価文60件を準備する。日→英30件、英→日30件。
- 日常文、メール、技術的な説明、否定・条件、数値・日付、一般的な慣用表現を含める。
- 40件をモデル・プロンプト選択に使い、残り20件は最終確認用として分ける。最終確認後に調整したら、別の文章で再確認する。
- 意味の反転、重要な条件・否定の脱落、重要な数値の変更、事実の追加を「重大な誤訳」と定義する。
- 初版の合格案: 最終確認20件で重大な誤訳0件、意味が保たれ実用的と判断できる訳18件以上。件数が小さいため、一般的な正答率の保証には使わない。
- Naniの結果は必要なら参考にするが、正解そのものとはしない。評価者と、判断できなかった文章を記録する。
- モデル名・ダイジェスト・量子化形式・プロンプト・生成設定を評価結果と一緒に記録する。

### 呼び出し・操作

- Safari、Chrome、プレビューのテキストPDF、標準テキストエディット、VS Code、利用中のターミナルで確認する。未導入アプリは未検証と記録する。
- 各アプリで日本語・英語を選択し、ショートカットから取得・表示・コピーできるかを記録する。
- 直接取得、コピー補助、手動コピーのどの経路で動いたかを区別する。
- 権限拒否、空選択、ショートカット競合、連続実行、スリープ復帰を確認する。
- コピー補助を有効にした場合は、既存クリップボードの復元と、途中でコピーし直した内容を上書きしないことを確認する。

### 性能目標（実測前の仮値）

- M4 Pro・48GBで測定し、OS・他アプリ・メモリ使用・採用モデルを記録する。
- ロード済みのモデルで、原文が日本語200文字以内／英語400文字以内の短文を対象とする。
- 各方向30回で、ショートカットからパネル反応まで200ms以内、最初の訳文表示まで5秒以内、翻訳完了まで20秒以内をそれぞれ95パーセンタイルの目標にする。
- 初回ロードを含む時間は別に測り、上記の結果に混ぜない。
- 未使用時は画面取得・クリップボード監視・推論を繰り返さない。
- 27Bが遅い場合は12Bを同じ品質基準で評価し、品質と待ち時間の両方から標準モデルを決める。

### オフライン・保存

- 初回セットアップ後、ネットを切った状態で起動・選択取得・翻訳・履歴参照を確認する。
- 通信の観測で、翻訳時に原文・訳文が外部へ送られていないことを確認する。アプリとOllama本体は別々に観測する。
- 履歴保存オフ、オン、再起動、個別削除、全削除を確認する。

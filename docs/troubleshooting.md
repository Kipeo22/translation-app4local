# トラブルシューティング

## 許可がオンでも、権限の案内が出る場合

ショートカットで「ことば」が開き、権限の案内が出る場合、キーは届いていますが、実行中のアプリがmacOSから許可されていません。開発中のアドホック署名はビルドごとに識別用のコードハッシュが変わるため、更新前のアプリへの許可が一覧に残っている可能性があります。

1. 「ことば」を終了します。
2. 権限画面でKotoba／ことばをいったんオフにし、再びオンにします。
3. 改善しない場合は、その項目を「−」で外し、「＋」で現在の `dist/Kotoba.app` を追加してオンにします。
4. アプリを開き直してから、他アプリで文章を選びCommand+Jを押します。

権限のオン操作はユーザーがシステム設定で行ってください。アプリの再ビルドはこの手順には不要です。

## 許可の案内は出ないが、選択した文章を取得できない場合

Accessibility APIに対応しないアプリでは、設定の「選択を取得できないとき、自動コピーで補助する」をオンにして試せます。操作は選択→キーのままです。アプリが内部でコピーし、復元可能なクリップボード内容を戻します。保護された入力欄は取得しません。任意のアプリでの取得は保証しません。

自動コピー補助は初期オフです。復元できない形式・大きなデータがクリップボードにある場合は補助を行いません。クリップボードの常時監視はしません。

また、アプリを開いた後にOSへ登録される「サービス」→「ことばで翻訳」から、選択文章を渡す経路もあります。サービスの表示にはOSの登録更新が必要な場合があります。アクセシビリティの許可がなくてもサービス経由と手入力は使えます。

## ビルド環境が見つからない場合

次のコマンドで、使用中の開発環境を確認してください。

```sh
xcode-select -p
xcodebuild -version
xcrun swift --version
xcrun --sdk macosx --show-sdk-version
```

Swift 6.2系以降とmacOS 26対応SDKが必要です。Command Line Toolsや古いXcodeが選択されている場合は、使用するXcodeの設定を確認してください。

## Apple Intelligenceが使えない場合

システム設定でApple Intelligenceが有効か、モデルの準備が完了しているかを確認してください。準備中や非対応の状態はアプリにも表示します。導入済みのOllamaローカルモデルがある場合は、設定からエンジンを切り替えて使えます。

## Ollamaの接続エラーが出る場合

Ollamaが起動していることと、設定した名前のローカルモデルが導入されていることを確認してください。アプリの接続先は`http://127.0.0.1:11434/api/chat`です。モデルはアプリから自動インストールしません。

解決しない場合は、公開できるダミー文章を使い、[不具合報告の案内](../CONTRIBUTING.md#不具合の報告)に沿ってIssueを作成してください。

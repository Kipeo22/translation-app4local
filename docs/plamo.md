# PLaMo 3によるローカル翻訳

## 初回の準備

1. Kotobaの設定から「PLaMo 3」を選びます。
2. 「モデルの利用条件」を確認し、「ダウンロードして準備」を押します。
3. 約1.83 GBの取得と検証が終わり、「準備完了」と表示されるまで待ちます。
4. 原文を入力・貼り付けして翻訳します。以後はオフラインで利用できます。

空き容量は3 GB以上が目安です。ダウンロードは中断できます。通常の中断・エラーでは一時ファイルを片付け、再試行時は先頭から取得します。準備中にウィンドウを閉じてもメニューバーにアプリが残っていれば取得を続けます。アプリを終了すると準備も中断します。

新規インストールの初期エンジンはPLaMoです。既存ユーザーの保存済みエンジン設定は変更しません。切り替えは画面上部または設定で行います。

## 保存先と実行方法

モデルと実行環境は次のアプリ専用フォルダに保存します。設定の「保存先を開く」から確認できます。

```text
~/Library/Application Support/Kotoba/PLaMo/plamo3-2b-q4km-llama-b12125/
```

モデルは `pfnet/plamo-3-translate-2b-GGUF` のQ4_K_M、実行環境はllama.cpp `b12125` macOS arm64です。取得元のリビジョンとSHA-256を固定し、検証後に実行環境を展開します。モデルの検証と導入全体が完了するまで利用可能とは扱いません。モデル重みや実行バイナリはGitリポジトリ・アプリのビルド成果物へ含めません。

翻訳時はアプリが専用のサーバープロセスを自動起動します。接続は `127.0.0.1` の一時ポートだけに限定し、起動ごとに認証キーとモデル名を生成します。ユーザーが別途起動したOllamaやllama.cppには接続せず、別エンジンへの切り替え・アプリ終了時に停止するのもアプリが起動したプロセスだけです。モデル読み込み中も翻訳を中断できます。

PLaMoのPFML3形式を直接Completions APIに渡します。context 8192、temperature 0.1、seed 42、出力上限4096トークンです。初回はモデルを読み込む時間がかかり、以後は起動済みのモデルを使います。途中で切れた通信・出力上限への到達・空の訳文を「翻訳完了」とは扱いません。

## ネット接続と利用条件

初回取得にはHugging Face・GitHubへの接続が必要です。翻訳原文・訳文はローカルサーバーへだけ送ります。推論サーバーのWeb UIとログ出力は無効にしており、アプリの翻訳履歴は従来どおり初期オフです。

モデルには[PLaMoコミュニティライセンス](https://huggingface.co/pfnet/plamo-3-translate-2b-GGUF/blob/f2b4599dff9b3e45c62567eac15e83186b4cb64e/LICENSE/ja)が適用されます。商用利用・再配布などの条件は原文を確認してください。実行環境にはllama.cppのMITライセンスが同梱されます。

## 困ったとき

- **準備が必要と表示される**：設定からモデルを取得してください。ダウンロード途中のデータは利用できません。
- **検証に失敗する**：取得ファイルのSHA-256が一致しませんでした。ネット接続・空き容量を確認して再試行してください。
- **導入先に不完全なデータがある**：保存先を開き、該当のバージョン用フォルダを別の場所へ移動して再試行してください。アプリは既存フォルダを上書きしません。
- **起動できない／タイムアウトする**：空きメモリを確認し、アプリを終了して起動し直してください。実行ファイルを手動で差し替えた場合は同じバージョンの配布物へ戻してください。
- **訳文が途中で止まる**：出力上限や通信中断の可能性があります。原文を短くして再試行してください。長文の自動分割は未実装です。

## 開発者向けの実機確認

通常の `zsh scripts/check.sh` はモデルをダウンロードしません。実モデル統合テストは次の環境変数を指定したときだけ実行します。

```sh
KOTOBA_PLAMO_CACHE=/absolute/path/to/translation-benchmark \
  swift test --filter PlamoIntegrationTests
```

キャッシュフォルダには公式配布の `llama.tar.gz` と `models/plamo-2b.gguf` を置きます。`KOTOBA_PLAMO_DOWNLOAD_RUNTIME=1` を追加すると、実行環境のみを実際にダウンロードしてURLSessionの取得経路も確認します。モデルは検証済みのキャッシュから読み込み、テスト専用の一時フォルダへ導入します。テスト後にサーバーを止め、一時フォルダを削除します。

2026-11-06、M4 Pro / macOS 27.2で初回導入、日英両方向の否定・条件・数値、中断後の再実行、未認証アクセス拒否、停止後の接続終了を確認しました。1.8 GBのモデル本体をURLSessionで再ダウンロードする試験は行っていません。実行環境はURLSessionで取得し、モデル本体は先のベンチマークで取得した同一SHA-256のキャッシュを使いました。

署名済みアプリの `--smoke-test-plamo` でも英→日の翻訳完了と画面表示を確認しました。この1回のコールド起動では最初の文字まで9.59秒、完了まで9.72秒でした。推論サーバーとモデルの読み込みを含むため、起動済みモデルで測ったベンチマークの応答時間とは条件が異なります。設定画面の「準備完了」表示も実画面で確認済みです。
